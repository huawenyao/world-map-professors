# 数字时代广场：增长、运营与组织

## 1. GTM 原则

1. **场景单点打穿，再横向复制。** 先成为一个场景里「选型 + 标准」的默认引用，再发全国总榜。
2. **先当维基，再当媒体。** 媒体节奏服从资产完整度，避免有热度无坐标。
3. **厂商销售卖分类，不卖名次。** 话术与合同模板写死。
4. **开发者与编辑是同一冷启动。** 没有 Tool/Agent YAML，广场只是文章站。

## 2. 冷启动剧本

### 2.1 旗舰场景（二选一，建议先软件研发）

仓库里已有 `technology/software-development` 与 `finance/wealth-management` 种子。MVP 选一个做「广场样板街区」：

| 步骤 | 动作 | 完成定义 |
|------|------|---------|
| 1 | 补全该场景资产：缺的角色/案例用模板补齐 | 场景页能讲完价值流 |
| 2 | 收录 20+ 产品、15+ 工具、15+ 人物、10+ 品牌 | 每条有来源与场景锚点 |
| 3 | 发布该场景双榜 v0 + 方法页 | 外部可引用链接 |
| 4 | 邀请 5 家产品认领 | 至少 3 家完成认证 |
| 5 | 给 Agent 开发者一份「按标准配置」教程 | 外部成功复现一次查询 |

### 2.2 传播顺序

1. 方法论文（为何双榜、为何场景坐标）→ 建立被引用的可能性  
2. 场景专题（不是人物八卦）→ 给搜索引擎和采购部门可落地的页面  
3. 周期榜 → 注意力  
4. 开放贡献者计划 → 补其他场景  

禁止第一步就做「全球 AI 富豪榜」。那会把品牌锁死在娱乐榜，后续 B 端无法溢价。

## 3. 渠道

| 渠道 | 用途 | 注意 |
|------|------|------|
| SEO / 场景落地页 | 长期流量 | URL 按 `industry/scenario/product` |
| GitHub 本体 | 开发者与审计 | README 指向广场方法 |
| 行业社群（研发、投顾、L&D） | 种子用户 | 用短名单，不用鸡汤 |
| 合作媒体 | 转载榜单时必须带方法链接 | 合同要求不得改名次解读 |
| 峰会 / 颁奖 | P2 以后 | 奖与赞助分离 |
| Agent 框架集成 | API 分发 | 对方文档里出现 `scenario_ref` |

## 4. 运营机制

### 4.1 委员会

- 方法委员会：榜单权重、剔除规则、版本发布  
- 行业编辑组：场景与案例  
- 利益冲突登记：持仓、顾问费、股权  

委员会名单公开。无名单的「专家评分」视为无效。

### 4.2 周期

| 周期 | 动作 |
|------|------|
| 周 | 新条、纠错、认领工单 |
| 月 | 旗舰场景覆盖度回顾、空态场景是否误上榜 |
| 季 | 发快照榜、方法是否升级、披露报告 |
| 年 | 方法大版本、行业包路线、颁奖（可选） |

### 4.3 贡献激励

- 采纳后的署名与贡献积分（沿用维基精神）  
- 高质量场景包可进入「署名编辑」  
- 不早期用现金买稿堆数量；P2 可对核实案例付事实核查费  

## 5. 组织（最小编制）

不按「媒体编辑部」堆人，按产线：

| 角色 | 职责 | 可兼岗 |
|------|------|--------|
| 广场产品 | IA、认领流、付费隔离 | 创始人 |
| 本体工程师 | Schema、校验、仓库 | 现有 world-professors |
| 行业编辑（旗舰场景） | 资产与条目质量 | 顾问兼职起步 |
| 信任与方法 | 榜单说明、申诉、披露 | 法务顾问支持 |
| 厂商运营 | 认领转化，严禁承诺名次 | P1 再加 |

AI 辅助生产初稿，人负责来源与坐标。编制增加应对着「未审核队列」而不是对着「发稿量」。

## 6. 中国市场与全球实体

- 全球品牌/产品可进广场，但 **场景包优先中文产业**。  
- 分榜：中国市场榜 / 全球榜，避免用美国热度给中国采购做唯一排序。  
- 人物榜遵守公开信息与更正删除。  
- 评测表述避免绝对化医疗/金融承诺；金融场景强调「非投资建议」，与 Agent 约束字段一致。

## 7. 风险运营清单

| 风险 | 监测 | 动作 |
|------|------|------|
| 广告化 | 精选点击占比、销售话术抽检 | 砍曝光套餐，公开审计 |
| 水军条目 | 来源重复度、新域集中 | 观察名单 |
| 名誉诉讼 | 申诉单 | 先下首页保留条目历史 |
| 本体与广场两套 CMS | 字段漂移 | 禁止平行数据库；广场字段回写 YAML |
| 选错旗舰场景 | 认领冷、API 无调用 | 换场景，不先加总榜 |

## 8. 与现有路线图的叠加

原 Phase 4–7（校验、CLI、示例数据、维基生成）**全部保留**，并且是广场 P0 的依赖：

- 没有 `validate`，广场条目会迅速腐烂  
- 没有 wiki/场景页，五馆无处挂载  
- 没有金融/科技示例，冷启动剧本无法执行  

广场不替代标准库，它把标准库变成能被看见、认领和订阅的产品。
