# 数字时代广场：产品规划

## 1. 产品形态

广场是一个 **工作台 OS + 开放数据仓库 + 查询 API**（对标 Success.ai 的 app 工作台，而不是百科站点）。

| 表面 | 给谁 | 形态 | Success.ai 类比 |
|------|------|------|----------------|
| plaza.app | 公众、厂商、企业采购 | 左侧模块工作台：发现、五馆、对比、认领 | app.success.ai |
| plaza.demo | 销售 / 讲解 | 一句工作流 + 模块块 + 对比表 + 打开工作台 | demo.success.ai/demo |
| Git `data/` | 贡献者、审计者 | YAML 单一事实源 | （对方无对应，我们多出来的公信力层） |
| API | Agent、HR/LMS | 只读查询 → 认领写入 | 对方的 Integrations & APIs |

可点击原型：`demo/plaza/`。对标分析：`docs/plaza/06-success-ai-reference.md`。

Phase 1 不自建复杂社交。关注、收藏、对比优先；Feed 与私信后置。

## 2. 信息架构

```
工作台 OS（左导航常驻）
├── 工作台            场景街区卡 + KPI + 运行中的解决方案
├── 场景发现          行业/场景/品类/适配度过滤（Lead Finder）
├── 解决方案          场景 SKU + 交付在跑（Campaigns）
├── AI Man            数字专才档案 + 改编台
├── 五馆
│   ├── 名人榜
│   ├── 品牌榜
│   ├── 产品榜
│   ├── 行业资产库
│   └── 工具库
├── 对比台
├── 认领队列
├── 方法
└── 套餐              访客 / 认证 / 企业坐标 / 场景解决方案
```

**主导航是场景发现与解决方案。五馆是选型；AI Man 是交付。**

### 3.6 场景解决方案页

- 出口条件、绑定流程、默认 AI Man、人机检查点
- 「启用交付」进入运行视图（步骤状态）
- 改编策略：相邻可改编、低适配拒绝

### 3.7 AI Man 页

- 强制「数字专才 / 非真人」
- 主场场景、能力、工具、约束
- 改编台：选目标场景 → 输出 fit、工具重绑、拒绝原因

主路径：发现场景 → 短名单 → **启用解决方案** → 检查点签收。

## 3. 核心对象与页面

每类对象一页，页内用同一套「坐标条」：行业、场景、角色、能力、工具。

### 3.1 人物主页（名人榜）

- 身份：真人 / 数字人格（强制标记）
- 坐标：主行业、主场景、能力标签（等级只展示有依据的）
- 关联：任职品牌、代表产品、开源/著作、贡献过的资产条目
- 双分：影响力分、专业贡献分（分开展示）
- 认领状态、来源与更新时间

### 3.2 品牌主页

- 组织类型、地域、成立与阶段（公开信息）
- 产品组合、工具出口、覆盖场景热力图
- 资产厚度：是否贡献/对齐标准流程与 Agent 定义
- 争议与合规记录（来源标注，允许申诉）

### 3.3 产品主页

- 品类、定价模式、平台、目标用户
- **场景适配表**（核心）：场景 → 替代/增强的角色 → 关键 KPI
- 集成的工具/模型、数据与合规声明
- 版本日志；与竞品的公开维度对比（功能存在性 + 场景适配，不做阴阳评分）

### 3.4 资产页（沿用并升级现有 wiki 对象）

- 场景页成为广场「街区」：一侧是流程/角色/Agent，一侧是该场景下的产品榜与工具短名单
- 角色页增加「对应真人能力路径」和「对应 Agent 边界」
- Agent 页保持可配置：能力、工具、约束、I/O Schema

### 3.5 工具页

- 在现有 Tool YAML 上增加广场字段：产品归属、调用热度（公开口径）、MCP/函数签名状态
- 适用步骤：挂到 Workflow.step.tools
- 「能被 Agent 用」与「能被人点」分开展示

## 4. 榜单产品规则

### 4.1 双榜制（强制）

| 榜 | 回答的问题 | 主要信号（示例） | 不可用的信号 |
|----|-----------|-----------------|-------------|
| 影响力榜 | 谁在被看见、被讨论 | 公开引用、检索、产品采用叙事、媒体与论文（分级加权） | 付费、粉丝买卖、自报 GMV |
| 专业贡献榜 | 谁在该场景真正贡献 | 开源/论文/标准引用、资产库采纳、可复核案例、工具被标准流程引用 | 纯曝光、公关稿数量 |

人物、品牌、产品都做双榜。工具库默认「场景适配榜」+「可调用完整度榜」，不做粉丝榜。

### 4.2 上榜资格

1. 至少 1 个有效 `scenario_ref`（或行业级条目的行业锚点）
2. 至少 2 个独立公开来源，或已认证认领
3. 数字人格必须披露模型/运营方
4. 连续两个计算周期无法复核来源则降为「观察名单」，不进正式榜

### 4.3 展示规则

- 分数展示为区间或等级亦可，避免伪精确到小数
- 每次发榜公布：方法版本、计算窗口、剔除规则
- 精选卡视觉上与有机榜严格区分

详细字段见 [04-data-model.md](04-data-model.md)。

## 5. 关键用户旅程

### J1 个人：我在这个场景该用什么、补什么

1. 选择行业/场景（或从职位描述匹配）
2. 看到该场景的角色演进（传统 → AI 增强 → Agent）
3. 看到产品短名单与工具短名单（场景榜，而非全局网红榜）
4. 打开能力差距（需登录后的简版自评）
5. 收藏学习路径（P2）

### J2 厂商：让产品出现在正确的街区

1. 搜索自己的产品（可能已被开放收录）
2. 认领 → 提交官方描述、场景标签、集成工具
3. 审核通过后获得认证标
4. 查看「出现在哪些场景短名单」（不展示竞品付费数据）
5. 可选购买该场景频道的精选位

### J3 开发者：按标准配一个投顾 Agent

1. 打开资产库场景 `scn-fin-wealth-mgmt`
2. 拉取 Workflow、Agent 定义、约束
3. 从工具库解析接口与权限
4. API 导出 JSON；本地对照现有 `StandardLibrary` 设想

### J4 企业 L&D：给财富顾问团队做 AI 能力框架

1. 订阅金融行业包
2. 导出角色能力矩阵
3. 映射内部职位（先手工，后模板）
4. 生成培训主题列表（指向能力学习路径）

## 6. MVP（最小可发布广场）

MVP 只证明一件事：**场景坐标能同时驱动榜、产品和工具。**

### 必须有

- 1 个完整行业包（建议：**科技 / 软件研发** 或 **金融 / 财富管理**，二者已有 YAML 种子）
- 该行业 ≥ 1 个场景的资产闭环：Industry, Scenario, Workflow, Agent, Capability, Tool
- 三类榜的 v0：人物、品牌、产品各 15–30 条（可先编辑精选，算法后置）
- 工具库挂到步骤与场景
- 方法页：双榜说明、非付费名次
- 认领表单（即使人工邮件审核）
- 静态或半静态站点可发布（MkDocs / 同类），条目来自 YAML

### 明确砍掉

- 社交 Feed、私信、关注推荐算法
- 自动爬全网打分
- 支付与自助精选位
- 多语言
- 通用「全行业 Top 100」大而空总榜（可有「观察榜」但不作为首页主推）

### MVP 验收

打开一个场景页，能在同一屏到达：流程、Agent、3 个产品、3 个工具、3 个人物、2 个品牌，且每条都有来源。

## 7. 功能演进（按依赖，不按月份）

### P0 地基

- 广场信息架构与场景首页
- Person / Brand / Product Schema 与仓库
- 与现有 Industry/Scenario/Tool 的引用完整性
- 编辑型 v0 榜单（YAML 维护）
- 方法与披露页

### P1 可运营

- 认领与认证工作流
- 产品对比（场景维度）
- 工具过滤（行业、接口类型、定价模式）
- 贡献 PR 流程文档化（沿用 Git）
- 简单搜索（名称与标签）

### P2 可收费

- 企业席位与行业包
- 只读 API（实体查询、场景短名单）
- 排名计算流水线（可复现）
- 精选位投放后台（与分数存储分离）
- 能力简版自评

### P3 基础设施

- 语义搜索、个性化（基于用户场景，而非娱乐推荐）
- 工具/Agent 分发与用量
- 能力认证
- 委员会工作台、申诉与审计日志

## 8. 内容生产（产品即编辑系统）

广场是内容密集型产品，功能开发必须给编辑让路。

| 产线 | 产出 | 质量门 |
|------|------|--------|
| 本体产线 | 场景、流程、Agent、能力 | Schema 验证 + 引用完整 |
| 榜单产线 | 人物/品牌/产品条目与周期榜 | 来源 ≥2、场景锚点、利益披露 |
| 工具产线 | Tool YAML + 广场包装字段 | 接口或等价描述、适用场景 |
| 认领产线 | 官方纠错 | 工单 SLA、变更 diff 公开 |

AI 可生成初稿，**正式条必须人审**。与现有原则一致：开放协作，但不是无审核 Wiki。

## 9. 体验原则

- **先给地图，再给排行。** 首页第一屏是场景入口，不是明星脸。
- **同一实体不拆五个站。** 人物页能去品牌，品牌能去产品，产品能去工具和流程。
- **数字人格不混充真人。** 默认视觉与文案隔离。
- **空态诚实。** 某场景产品不足 5 条时显示「覆盖不足」，禁止用无关网红产品凑数。
- **移动端可读榜和场景，复杂对比引导到桌面。**

## 10. 指标（产品，不是虚荣）

| 类型 | 指标 | 含义 |
|------|------|------|
| 坐标密度 | 正式产品/工具中含有效场景锚点的比例 | 是不是广场而不是导航站 |
| 闭环率 | 场景页到产品/工具/人物的点击完成率 | 五馆是否真的互链 |
| 信任 | 方法页阅读、申诉量、名次相关投诉 | 公信力 |
| 供给 | 认领通过数、贡献采纳率 | 飞轮是否转 |
| 价值 | 场景短名单被导出/API 调用次数 | B 端是否在用坐标 |
| 健康 | 精选位点击 / 有机榜点击 | 是否广告化 |

不把「上榜条数」当核心 KPI。条数膨胀而锚点变少，就是在自毁。
