# 场景解决方案服务 · AI Man

广场五馆回答「看见谁、用什么」。这一层回答：**谁来把这个专业场景做完，并且换场景时如何自适应。**

这是真正的 AI 原生交付，而不是把 Chatbot 贴在目录上。

## 1. 一句话

**场景解决方案服务** = 按行业场景打包的可交付作业。  
**AI Man** = 绑定场景坐标的数字专才：流程 + 能力 + 工具 + 约束 + 人机检查点；换场景时先算适配，再改编或拒绝。

Success.ai 里真正赚钱的不是 Lead 列表，是战役在跑（写、发、收回、跟进）。广场对应物不是再做一个榜，而是让 AI Man **在场景里跑完一次交付**。

```
五馆（看见 / 选型）
        ↓
场景解决方案（成交物：一次专业交付）
        ↓
AI Man（执行者：场景自适应的数字专才）
        ↓
world-professors（坐标系：场景 / 流程 / Agent / 能力 / 工具）
```

## 2. 什么叫「AI 原生」，什么不是

| 不是 AI 原生 | AI Man 原生 |
|-------------|-------------|
| 通用助手 + 一段 prompt | 先绑定 `scenario_ref` + `workflow_ref`，再说话 |
| 工具导航「你自己去装 Copilot」 | 解决方案把工具挂到流程步骤上，按步骤调用 |
| 换行业只换皮肤 | 换场景先做能力差距、工具重绑、约束重载 |
| 「什么都能干」的万能数字人 | 相邻场景可改编；跨域低适配则拒绝或强制人工 |
| 数字人格做名人榜皮套 | 名人榜是被看见；AI Man 是被交付 |

数字人格（Persona）可以出现在名人榜。  
Agent 是标准库里的规格。  
**AI Man 是规格被部署之后、带着 SLA 和检查点跑作业的实例。**

## 3. AI Man 能力模型

一个 AI Man 必须同时具备五件套，缺一不可称为「专业场景自适应」：

1. **场景主场** `home_scenario`：默认作业街区（如软件研发）。
2. **可执行流程** `workflows[]`：步骤、输入输出、工具、是否要人确认。
3. **能力剖面** `capabilities[]`：等级来自能力库，不是自我介绍。
4. **工具编排** `tools[]`：从工具库解析接口；换场景可重绑。
5. **约束与升级** `constraints` + `escalation`：合规、金额、置信度 → 转人。

### 自适应算法（产品规则，不是营销词）

```
输入: AI Man M, 目标场景 S'
输出: AdaptPlan

fit = 能力覆盖(S'.required ∩ M.capabilities)
     × 流程可执行(S'.workflows 可映射到 M.workflows)
     × 工具可重绑
     × 约束可加载

IF fit = high AND 相邻（同行业或高迁移能力）
  THEN 自动改编：换 workflow、加/减 tool、保留人机检查点
IF fit = medium
  THEN 半自动：列出缺口能力，插入额外人工门，报价上浮
IF fit = low 或 监管场景且缺领域能力
  THEN 拒绝自动交付，只允许「人工专家 + AI Man 辅助」或改派主场匹配的 AI Man
```

**自适应的诚实性**：会拒绝，才是专业。软件研发 AI Man 不得假装能做财富管理投顾。

## 4. 场景解决方案（商品）

解决方案是卖给客户的 SKU，AI Man 是里面的劳动力。

```
解决方案
├── 目标场景与成功口径（KPI / 出口条件）
├── 绑定流程（Workflow）
├── 默认 AI Man
├── 人机检查点（哪些步骤必须人签）
├── 工具短名单（来自工具库，可被产品榜条目实现）
├── 交付模式  assisted | human-gated | autonomous（默认 human-gated）
├── SLA 与计量（按交付单元 / 月包并发）
└── 改编策略（相邻场景列表 + 禁改编列表）
```

旗舰样例（本仓库已有种子）：

| 解决方案 | 场景 | AI Man | 出口 |
|---------|------|--------|------|
| 功能开发场景解决方案 | `scn-tech-software-dev` | 研发交付 AI Man | 可合并分支 + 审查记录 + 测试 |
| （空态）财富管理客户画像 | `scn-fin-wealth-mgmt` | 不应用研发 AI Man 硬上 | 显示「需投顾主场 AI Man」 |

## 5. 工作台模块（对标 Success.ai 的「战役在跑」）

| Success.ai | 场景解决方案 |
|-----------|-------------|
| 建 Campaign | 启用一个场景解决方案 |
| AI Writer 写邮件 | AI Man 执行流程步骤 |
| 序列 delay / A/B | 步骤依赖 + 人机门 |
| Inbox 处理回复 | 检查点队列（待人确认） |
| Analytics | 自动化率、门通过率、改编拒绝率 |

左导航新增（在五馆之上，因为它是成交层）：

```
工作台
场景发现
解决方案     ← 商品目录 + 运行中的交付
AI Man       ← 数字专才档案 + 改编台
五馆 …
认领队列
方法
套餐
```

主路径升级为四步：

1. **发现场景**（Find）
2. **看街区短名单**（Shortlist：人/品牌/产品/工具）
3. **启用解决方案**（Engage：AI Man 开跑）
4. **检查点签收**（Close：人确认或改编/改派）

## 6. 商业模式增量（R9）

这是广场里 **愿付最高** 的一层：客户预算在「把这件事做完」，不在 Banner。

| 编号 | 收入 | 客户 | 计量（两个数字） | 阶段 |
|------|------|------|-----------------|------|
| R9 | 场景解决方案 | 业务团队 / 数字化 | **并发 AI Man × 场景包** | P1 Demo，P2 可计费 |
| R9b | 改编加价 | 要跨相邻场景 | 中适配加人工门，报价上浮 | P2 |
| R9c | 人工专家加塞 | 低适配 / 强监管 | 人时，不伪装成全自动 | P2 |

套餐增加第四档（仍不卖名次）：

| 档 | 两个数字 | 买到什么 |
|----|---------|---------|
| 场景解决方案 | 并发 AI Man 数 · 开通场景包数 | 按流程交付、检查点、改编台 |

合同话术：买的是 **「软件研发功能交付，带 3 个人机门」**，不是「一个会聊天的数字人」。

健康度：

- 改编拒绝率要可见（防止销售逼 AI Man 万能）
- 人机门跳过率过高 = 事故，不是效率
- R9 收入占比上升，R2 精选占比下降，才算从媒体做成交付

## 7. 与现有实体的边界

| 实体 | 回答 | 不承担 |
|------|------|--------|
| Person / 数字人格 | 被看见 | 不跑 SLA |
| Agent YAML | 标准作业规格 | 不直接向客户报价 |
| Tool | 可调用接口 | 不是解决方案 |
| **AI Man** | 部署后的数字专才 | 不进真人名人榜 |
| **Solution** | 可售交付包 | 不修改有机名次 |

AI Man 若需要公共形象，可 *关联* 一条 digital-persona，但页面必须写「交付实例 / 非真人」。
