# 数字时代广场：商业模式

## 1. 模式选择

广场采用 **媒体注意力 × 知识基础设施 × 双边市场** 的混合模式。

| 模式 | 在广场中的位置 | 作用 |
|------|----------------|------|
| 媒体 / 榜单 | 三榜 | 获客、公信力、议程设置 |
| 知识基础设施 | 行业资产库 + 本体 | 高壁垒、可 API 化、可被 Agent 消费 |
| 市场 / 目录 | 工具库 + 产品入驻 | 供给侧付费、交易与分发 |
| 会员 / 身份 | 认领、认证、主页 | 把「被正确描述」变成付费点 |
| **场景交付** | **解决方案 + AI Man** | **把场景做完：流程在跑、检查点签收、跨场景改编** |

**刻意不做**：出卖名次、黑箱综合分、纯广告门户。名次一旦可买，坐标系立刻失效，后面所有 B 端溢价归零。

## 2. Business Model Canvas

| 模块 | 内容 |
|------|------|
| **客户细分** | ①转型中的知识工作者 ②Agent/应用开发者 ③企业 L&D、HR、数字化 ④品牌/产品/工具厂商 ⑤投资与研究机构 |
| **价值主张** | 用同一套产业坐标回答：关注谁、信任谁、用什么、行业如何被改写、工具如何被调用 |
| **渠道** | 广场 Web、开放数据/Git、年度榜单与报告、开发者 API、行业峰会、合作媒体 |
| **客户关系** | 免费浏览；认领与审核；专家委员会；贡献者声誉；企业成功服务 |
| **收入流** | 见第 4 节：入驻认证、企业订阅、API、报告、活动、市场抽成（名次除外） |
| **核心资源** | 本体与方法论、结构化条目、审核网络、榜单品牌、工具 Schema |
| **关键业务** | 条目生产与审核、排名计算、场景覆盖、API、厂商入驻运营 |
| **重要伙伴** | 行业学会与协会、开源社区、云厂商、高校、媒体、HR/LMS、Agent 框架 |
| **成本结构** | 编辑与行业研究员、审核专家、工程、法务合规、带宽与模型调用、品牌活动 |

## 3. 增长飞轮

```
        三榜带来注意力
              │
              ▼
     人 / 品牌 / 产品主动认领
              │
              ▼
     场景与能力标注更完整 ──► 资产库变厚
              │                      │
              ▼                      ▼
     工具可被检索、被 Agent 调用     榜单权重更有依据
              │                      │
              └──────────► 更多注意力与入驻 ◄─┘
```

辅助飞轮（B 端）：

```
企业用资产库做岗位/Agent 标准
        → 内部工具选型回到工具库
        → 使用与缺口数据（脱敏）反哺场景覆盖
        → 报告与 API 更值钱
```

**冷启动顺序**（不可反）：先做透 1 个行业的资产库 + 对应产品/工具映射，再发该行业的三榜。没有坐标的榜，只是稿费媒体。

## 4. 收入架构

所有商业产品必须满足：**不修改排名分数，不隐藏负面信息，付费位显著标注。**

### 4.1 收入矩阵

| 编号 | 收入 | 客户 | 触发点 | 与名次关系 | 阶段 |
|------|------|------|--------|-----------|------|
| R1 | 认证主页 / 认领 | 名人、品牌、产品 | 「这是我，请按官方信息展示」 | 无 | P1 |
| R2 | 精选曝光位 | 品牌、产品、工具 | 广场首页/频道的广告位 | 标注「精选」，不进分数 | P1–P2 |
| R3 | 企业广场订阅 | L&D / 数字化 / 战略 | 能力诊断、对比、私有收藏、席位 | 无 | P2 |
| R4 | 标准库 / 本体 API | Agent 平台、HR SaaS | 按调用或按年授权 | 无 | P2 |
| R5 | 榜单与产业报告 | 投资、媒体、企业战略 | 季报、年榜、定制切片 | 报告引用公开方法 | P2 |
| R6 | 工具/Agent 市场抽成 | 厂商与买家 | 线索、订阅分销、成交 | 无 | P3 |
| R7 | 认证与学习 | 个人与企业 | 能力认证、学习路径、培训授权 | 无 | P3 |
| R8 | 广场活动 / 颁奖 | 品牌与机构 | 峰会、行业夜 | 奖项由委员会，赞助是赞助 | P2–P3 |
| R9 | 场景解决方案 | 业务 / 数字化 | 启用 AI Man 跑完场景流程 | 无（交付不改名次） | P1 Demo / P2 计费 |

### 4.2 定价逻辑（方向，非最终价）

**个人**

| 档 | 权益 | 定价方向 |
|----|------|---------|
| 广场访客 | 浏览榜单与条目、基础搜索 | 免费 |
| 广场居民 | 关注、对比 3 个产品、个人能力收藏、贡献草稿 | 低价年费或邀请 |
| 认领者 | 认证标、官方链接、纠错工单、展示作品集 | 个人免费认证 + 反垃圾审核；机构代运营另计 |

**厂商（品牌 / 产品 / 工具）**

| 档 | 权益 | 定价方向 |
|----|------|---------|
| 开放收录 | 编辑根据公开资料建条 | 免费（不可控文案） |
| 认领认证 | 官方描述、版本日志、场景标签纠错、联系入口 | 年费，按产品数 |
| 增长套件 | 精选位、场景关键词报告、竞品公开对比导出、线索表单 | 年费 + 曝光 |
| 生态套件 | 工具进 Agent 目录、OpenAPI/MCP 托管、调用统计（厂商可见自己的） | 年费 + 用量 |

**企业（使用方）**

| 档 | 权益 | 定价方向 |
|----|------|---------|
| 团队 | 多席位、行业包、对比、学习路径 | 按席 × 行业包 |
| 专业 | 能力差距诊断、角色演进图、工具短名单 | 年费 |
| 平台 | 本体 API、私有映射、SSO、审计日志 | 年费 + 调用 |
| **场景解决方案** | 并发 AI Man × 场景包；改编加价；低适配只许人机 | 按交付单元或月包 |

**开发者**

| 档 | 权益 | 定价方向 |
|----|------|---------|
| 开放查询 | 公开 YAML / 限速 API | 免费 |
| 生产调用 | SLA、高限额、Webhook | 用量或年费 |
| 转授 | 把本体嵌入商业 Agent 产品 | 分成或许可证 |

### 4.3 单位经济（规划假设，用于验算而非承诺）

以 P2 稳态一年为验算框架：

- 广场 MAU 的变现不靠对个人收重税，靠 **1%–3% 的厂商入驻** 与 **几十家企业订阅**。
- 一份「场景级短名单 + 能力矩阵」对企业的替代品是咨询项目，定价应落在「订阅而非项目制」区间，用标准资产复制交付。
- API 的目标客户是 Agent 框架与 HR/LMS，毛利高，但需先有覆盖密度。

**健康度指标**：

- 认证收入 / 精选曝光收入 ≥ 1（避免广告化）
- 付费客户中「使用资产库或 API」的比例持续上升（避免纯买流量）
- 贡献者内容采纳率与专家审核通过率（避免 UGC 溃坝）

## 5. 谁付钱、为什么付钱

| 付钱方 | 真实预算科目 | 他们买的不是 |
|--------|-------------|-------------|
| 产品市场 / 增长 | 获客与品牌 | 不是买第一名，是买「出现在财富管理×投顾场景」 |
| 开发者生态 | 工具分发 | 不是 Banner，是被 Agent 标准库检索到 |
| L&D / HR | 培训与人才 | 不是课包堆砌，是岗位演进和能力尺子 |
| 数字化 / 业务 | 把场景做完 | 不是聊天机器人，是带检查点的 AI Man 交付 |
| 投资研究 | 数据 | 不是通稿，是可复核的覆盖与引用 |

销售话术必须对准预算科目。对外合同拆成四张菜单：**认证主页、产业坐标订阅、Agent 标准 API、场景解决方案（AI Man 交付）**。

## 6. 护城河（按形成顺序）

1. **方法公开的榜单品牌**（最快被看见，也最快被抄）  
   护城河弱，只负责点火。
2. **场景坐标密度**（中期）  
   每个产品/工具都有行业×场景×角色边，抄榜单抄不走这张图。
3. **可调用本体**（中期）  
   Agent 按标准拉流程与约束，切换成本开始出现。
4. **认领网络与纠错日志**（中期）  
   官方主页 + 版本历史 = 类维基的事实层。
6. **交付轨迹与改编拒绝率**（长期，R9）  
   解决方案在真实场景里跑过、敢拒绝低适配，咨询项目复制不了这条操作日志。

## 7. 竞争与替代风险

| 风险 | 表现 | 应对 |
|------|------|------|
| 导航站用更全的工具列表抢 SEO | 覆盖比你快 | 不拼数量，拼「挂得上场景的正式条」；SEO 落地页按场景而非按字母表 |
| 大厂做 AI 商店 | 分发能力强 | 做中立坐标与跨厂商比较；商店是货架，广场是地图 |
| 咨询公司做行业报告 | 客户关系深 | 报告订阅化、资产开源一层，咨询做不到每周更新的 Git 本体 |
| 榜单被质疑黑箱 | 公信力崩 | 开源权重说明、可导出计算底表、付费隔离审计 |
| 厂商不入驻 | 供给侧冷 | 先用公开资料建条（维基模式），认领是纠错权不是生存权 |

## 8. 合规与信任（商业前提）

- **排名审计**：算法说明、版本号、计算日、申诉窗口。
- **利益披露**：条目若与股东、广告主、关联公司有关，必须披露。
- **人物与品牌**：名誉权、肖像、商标；名人榜以公开职业信息为主，提供删除与更正。
- **行业资产**：不收录未授权的专有数据；案例需来源。
- **工具库**：不提供破解、绕过、未授权扫描类条目。
- **中国市场**：榜单与评测内容按资讯/科技媒体规范审核；企业 API 合同含数据出境与训练用途限制。

没有这一节，R1–R8 都不可售。

## 9. 三年商业叙事（阶段，而非日历）

**阶段 A · 坐标点火**  
一个旗舰行业（建议金融或科技研发）资产库可演示 + 该行业三榜 v0 + 工具映射。收入几乎为零，目标是方法被引用。

**阶段 B · 入驻与订阅**  
认领认证、精选位、第一批企业席位、只读 API。目标是验证「厂商为正确分类付钱、企业为坐标付钱」。

**阶段 C · 基础设施**  
Agent 标准调用、工具市场、认证体系、多行业复制。目标是经常性收入以 R3+R4+R6 为主，R2 占比下降。

判断升华成功的商业信号：**客户续约理由是「我们的岗位/Agent 按广场坐标来」，而不是「我们买了个 Banner」。**
