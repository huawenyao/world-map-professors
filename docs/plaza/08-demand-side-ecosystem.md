# 需求方生态：找人、找企业、评估链接、场景交付

> 交互语法对标 [Apple App Store](https://apps.apple.com)：Today、分类货架、资源详情、Get、资料库。  
> 资源单元是**个人与企业**，不是 App。  
> 评估尺子仍参考海汇（场景适配 / 贡献 / 可交付）；资料库承接小豆芽式任务闭环。  
> **不做**：把商店做成冷邮件 OS、灯笼街、矩阵分发。

## 1. 这一版纠正什么

上一版 Demo 把「人感」做成了傍晚街道、灯笼和闲聊，产品看起来像故事站，而不是**资源生态**。

需求方真正要买的不是气氛，而是：

1. **供给**：平台上有哪些达人、实践者、数字专才、品牌、企业可被调用  
2. **评估**：谁适合这个场景、贡献是否可复核、身份是否可信  
3. **链接**：短名单、建联、合作项目  
4. **交付**：合作战役跑起来，关键节点由人签收  

主用户是 **资源需求方**（品牌主、企业合作、项目负责人、代理商），不是逛街的游客。

## 2. 生态价值（必须写在产品表面）

```
需求方 brief
    │
    ▼
┌──────────┐   评估坐标系    ┌──────────┐
│  找人    │◄──────────────►│ 找企业   │
│ 达人/专才│   场景 × 贡献   │品牌/机构 │
└────┬─────┘                └────┬─────┘
     │         短名单 / 建联      │
     └────────────┬──────────────┘
                  ▼
           合作项目（Campaign）
                  ▼
        交付：解决方案 / AI Man / 人机门
```

五馆不再是「逛馆」，而是生态的 **供给库存**：

| 库存 | 需求方拿来干什么 |
|------|------------------|
| 人 | 找达人、实践者、数字专才；评估后再建联 |
| 品牌 | 找企业合作、联合方案、生态位 |
| 产品 | 看对方拿什么交付，避免只看牌子 |
| 资产 | 场景/流程/能力，决定「能不能接这单」 |
| 工具 | 交付时实际调用的接口 |

world-professors 是评估尺子：名次不可买；无场景锚点不上正式供给。

## 3. 参考了什么、不抄什么

### 3.1 App Store → 发现与详情；资料库承接合作

| 对方 | 广场 |
|------|------|
| App | **个人** 或 **企业** |
| Today / 货架 / 搜索 | 发现人与企业 |
| Get | 建联 / 合作 / 调用，写入资料库 |
| Library | 已加入、进行中、通知 |
| In-App Event | 数字专才交付活动 |

Success.ai 的战役语法只留在资料库与交付活动里，不再当第一屏。不抄冷邮件、域名预热、发信量。

### 3.2 新榜小豆芽 → 需求侧运营闭环

小豆芽是创作者/门店的 **内容运营工具**（多账号、发布、评论私信、任务中心）。广场只借其 **需求方闭环**，不借分发器：

| 小豆芽 | 广场对应 | 明确不做 |
|--------|---------|---------|
| 任务中心（品牌品宣任务） | 合作项目 | 一键发抖音/小红书 |
| 评论/私信聚合 | 合作收件箱 | 50+ 账号免密登录 |
| 数据复盘 | 评估与方法 | 混剪、封面工厂 |
| 团队协同 | 短名单与项目成员（P1） | 矩阵号管理 |

### 3.3 新榜海汇 → 达人评估与链接

海汇才是「品牌方找达人」的近亲：Brief → AI 荐号 → 评分与理由 → 报价/建联 → 企业达人库。

| 海汇 | 广场 | 我们多出来的 |
|------|------|-------------|
| 找号 Brief | 找人：场景 + 身份 + 适配 | 同一套尺子再用于 **找企业** |
| 内容调性/匹配理由 | 评估卡：场景适配、贡献、可交付、身份披露 | 数字人格强制非真人；AI Man 不进达人榜 |
| 荐号包 | 短名单 | 可同时放入人 + 企业 |
| 投放战役 | 合作项目 + 场景交付 | 交付可以是 AI Man 人机门，不只有投放作品 |
| 粉丝/报价主轴 | **禁止**用粉丝数当正式名次 | 专业贡献与场景适配才进评估 |

## 4. 功能架构

```
工作台 OS
├── 工作台         需求方首页：进行中项目、待评估、待签收
├── 找人           Lead Finder：达人 / 实践者 / 数字专才
├── 找企业         Lead Finder：品牌 / 实验室 / 可合作组织
├── 评估           场景适配 + 贡献 + 可交付 + 匹配理由
├── 短名单         人与企业混排，准备建联
├── 合作项目       Campaigns：从 brief 到交付
├── 交付           运行中的解决方案 / 人机检查点
├── 收件箱         建联 · 认领 · 驳回（名次不可买）
├── 供给库存       五馆（人/品牌/产品/资产/工具）
├── 方法           评估口径与付费隔离
└── 套餐           浏览 / 建联 / 交付
```

主路径（对标 Find → Contact → Close）：

1. **找**人 or 企业（先锁场景）  
2. **评估**后进入短名单  
3. **链接**为合作项目  
4. **交付**并在检查点签收；低适配拒绝，不拿错误供给充数  

## 5. MVP 范围（本 Demo）

样例场景仍是 **科技 / 软件研发**。

- 找人：2 条人物样例 + 1 名数字专才（阿码，非达人榜）  
- 找企业：GitHub / Anthropic / OpenAI  
- 评估：场景适配理由；财富管理显示覆盖不足  
- 合作项目：功能交付进行中；企业合作建联中；财富管理不可用  
- 收件箱：认领 + 「买第一名」驳回  

数字人格与 AI Man 仍不得伪装成真人达人。付费仍不得改名次。
