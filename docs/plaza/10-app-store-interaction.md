# 交互重构：App Store 语法，资源是人与企业

广场的公共表面不再做成 Success.ai 式左导航 OS，也不做街景。  
**对标 Apple App Store 的发现与详情**，差比只有一句：货架上不是 App，而是**个人**和**企业**。

## 1. 为什么换语法

需求方选人、选企业，和用户在 App Store 选 App 是同一类决策：

1. 先被编辑专题看见（Today）
2. 再按分类货架逛（人 / 企业）
3. 打开详情页看预览、说明、评估、信息表
4. 点 **Get** 装进自己的库
5. 在资料库里管理已加入的资源、更新与交付

Success.ai 适合「战役操作系统」。广场的第一表面是**资源商店**：先决定调用谁、合作哪家，再进入交付。

## 2. 对象映射

| App Store | 广场 | 不要做成 |
|-----------|------|---------|
| App | **个人**（实践者 / 达人） | 把人做成冷邮件线索行 |
| App（Games 分栏） | **数字人格 / 数字专才**（单独货架） | 和真人混进同一张达人榜 |
| App（Apps 分栏） | **企业**（品牌 / 实验室 / 机构） | 只有产品导航、看不见可合作主体 |
| Developer | 企业主页；人挂靠企业 | 人与公司无法互跳 |
| Today | 编辑专题：今日人物 / 今日企业 | 灯笼街、Feed 闲聊 |
| Games / Apps 页 | **人** / **企业** 两个货架页 | 五馆平铺 |
| Search | 搜人、搜企业、搜场景 | 只有关键词云 |
| Get | **建联**（人） / **合作**（企业） / **调用**（数字专才） | 购买名次、下载安装包 |
| Library / 已购 | **资料库**：短名单、进行中、通知 | 再做一套 CRM 左栏当首页 |
| Screenshots | 场景切片、作品、产品组合 | 无关美图 |
| Ratings & Reviews | 场景适配 + 专业贡献 + 可复核来源 | 粉丝星级、买来的评分 |
| Top Charts | 场景贡献示意榜 | 可买的正式名次 |
| Category | 行业场景 | 用研发分类填财富管理 |
| In-App Events | **交付活动**（解决方案 / 人机门） | 聊天套壳 |
| Age / Privacy | **身份披露**（真人 / 非真人 / 运营方） | 数字人格冒充达人 |
| Apple Ads | `data/plaza/ads/` 精选位 | 写进 RankingSnapshot |

## 3. 信息架构

```
Plaza Store
├── 今日 Today        大卡专题，底部嵌资源行 + Get
├── 人                精选货架 / 真人示意榜 / 数字人格货架 / 场景分类
├── 企业              精选货架 / 示意榜 / 实验室 / 场景分类
├── 搜索              建议词 + 结果行（图标、名称、副标题、Get、预览）
└── 资料库            已加入、进行中的合作、通知、账户
        │
        ├── 个人详情     图标 · 名称 · 副标题 · Get · 预览 · 说明 · 评估 · 信息 · 相关
        ├── 企业详情     同上；产品与旗下个人 = More by this developer
        └── 交付活动     从数字专才「调用」进入，人机门签收
```

底栏五 Tab 常驻，对标 App Store：Today · Games · Apps · Search · Arcade/Library。  
Arcade 位置给**资料库**（已调用的人与企业），不是游戏订阅。

## 4. 详情页（资源 = App 产品页）

每个个人 / 企业一页，结构固定：

1. **Header**：圆角图标、名称、副标题（角色或合作切口）、Get
2. **Preview**：3 张场景/产品切片，横向滑动
3. **Description**：可展开说明；样例条目必须写明非正式排行
4. **评估**：场景适配、专业贡献带、可交付；**不用粉丝数当星级**
5. **Information**：身份、场景、提供方、来源数、名次不可买
6. **More by**：企业旗下的人 / 产品；人跳回所属企业
7. **You might also like**：同场景相关资源；低覆盖场景空态

Get 之后按钮变为「已加入」，资源进入资料库，等价于 App Store 的已下载，而不是付费改名次。

## 5. 硬约束（交互层也要执行）

- 真人示意榜 **不得** 混入数字人格、AI Man。
- 数字人格 / 数字专才单独货架，标题区强制非真人。
- 财富管理分类与搜索：覆盖不足空态，**不得** 用软件研发供给填充。
- 排行货架标注「样例示意，非正式排行」。
- 要求总榜第一的通知直接驳回。
- 广告/精选与有机货架视觉可区分。

## 6. 交付仍在，只是不再当首页

作战室保留为 App Store 的 **In-App Event / 交付活动**：从数字专才详情的「调用」进入。  
资料库里的「进行中」承接合作状态。不在第一屏做 CRM 战役瓷砖。
